# Instrucciones para clasificar incidencias

Clasifica cada incidencia por su problema o solicitud principal, no por productos mencionados solo como comparación. Debes leer el título y el texto completo de cada registro asignado. La herramienta `read` trunca líneas largas: usa Python mediante `shell` para imprimir registros concretos o rangos pequeños con `json.dumps(..., ensure_ascii=False, indent=2)`.

Produce un objeto JSON por incidencia, en una sola línea, con exactamente estas claves:

```json
{"id":"codex-...","tipo":"bug|enhancement|documentation","superficie":"app|CLI|extension|codex-web|iOS","areas":["..."]}
```

`areas` debe ser un array (puede estar vacío), sin duplicados, usando únicamente valores de la lista permitida. Conserva el orden de entrada de las incidencias.

## Tipo

- `bug`: error, fallo, bloqueo, cierre inesperado, regresión, comportamiento incorrecto, problema de seguridad, lentitud o consumo anómalo. También informes retirados sin contenido si no hay mejor evidencia.
- `enhancement`: nueva funcionalidad, opción de configuración, mejora de UX o cambio solicitado que no describe principalmente un fallo actual.
- `documentation`: falta o mejora de documentación, solicitud de procedimiento/capacidades soportadas, o pregunta principalmente informativa/de uso.

## Superficie (exactamente una)

- `CLI`: codex-cli, `codex exec`, TUI/terminal, app-server/daemon cuando el flujo principal es CLI, instaladores del CLI y herramientas de línea de comandos.
- `extension`: extensión de VS Code/Cursor y extensiones de Chrome/Edge u otro navegador.
- `codex-web`: interfaz web de Codex/ChatGPT, Codex Cloud y tareas/entornos cloud cuando no sean específicos de la app de escritorio; conector/revisiones de GitHub.
- `iOS`: incidencias cuyo foco principal sea iPhone/iPad/iOS/iPadOS.
- `app`: app de escritorio Windows/macOS/Linux, app móvil distinta de iOS, Dots/Work/Computer Use en esas apps, y fallos genéricos de aplicación. Si una incidencia mezcla app y web, elige donde ocurre el fallo principal. Si mezcla varias plataformas de escritorio, sigue siendo `app`.

## Áreas permitidas y criterios

Valores exactos: `windows-os`, `sandbox`, `app-server`, `connectivity`, `TUI`, `session`, `rate-limits`, `tool-calls`, `browser`, `remote`, `model-behavior`, `performance`, `mcp`, `auth`, `context`, `subagent`, `config`, `computer-use`.

Pueden corresponder varias áreas, pero incluye solo las respaldadas por el contenido principal; evita añadir toda área mencionada incidentalmente.

- `windows-os`: comportamiento específico de Windows, ACL, CreateProcess, WSL, drivers o integración con Windows. No lo uses solo porque el sistema operativo figure en metadatos si el problema no es específico de Windows.
- `sandbox`: sandbox, permisos de ejecución, aprobaciones, políticas de ejecución, acceso de archivos/red restringido o bloqueos `blocked by policy`.
- `app-server`: app-server, daemon, actualizaciones/reinicios del daemon, inicialización backend JSON-RPC.
- `connectivity`: red, DNS, proxy, WebSocket/SSE, desconexiones/reconexiones, HTTP 403/5xx, Cloudflare, timeouts de conexión.
- `TUI`: representación o interacción de la interfaz de terminal: teclado, ratón, portapapeles, colores, texto, renderizado.
- `session`: chats/threads, reanudación, historial, archivado, estado de turnos o continuidad de conversaciones.
- `rate-limits`: cuotas, límites de uso, créditos, resets, capacidad del modelo y errores de modelo saturado.
- `tool-calls`: ejecución o catálogo de herramientas, `exec_command`, `write_stdin`, hooks, llamadas que fallan o resultados de herramientas.
- `browser`: navegador integrado/automatización, cookies, extensiones de navegador, páginas/iframes o control del navegador.
- `remote`: SSH/remoto, control de otro ordenador, emparejamiento, sincronización entre dispositivos o equipos conectados. No todo trabajo cloud es `remote`.
- `model-behavior`: calidad o comportamiento del modelo, afirmaciones falsas, razonamiento, selección/disponibilidad de modelos o esfuerzo de razonamiento. Para capacidad/cuota usa sobre todo `rate-limits`.
- `performance`: lentitud, latencia excesiva, bloqueos de rendimiento, CPU/RAM/disco o consumo de recursos.
- `mcp`: MCP, servidores/herramientas MCP, transporte o sesiones MCP.
- `auth`: login, autorización, cuentas, tokens/JWT, suscripciones/permiso de cuenta cuando sean el foco.
- `context`: ventana de contexto, tokens, compactación, instrucciones personalizadas o recuperación de contexto.
- `subagent`: subagentes, navegación/control de subagentes o flujo padre-subagente. No lo uses para cualquier tarea delegada cloud.
- `config`: archivos/valores de configuración, settings, opciones de configuración, configuración de modelos/herramientas.
- `computer-use`: Work/Computer Use, control del ordenador, capturas de pantalla, clicks, aprobaciones interactivas del escritorio o automatización local de UI.

## Registros retirados, duplicados o incompletos

Clasifica igualmente todos los registros, incluso si están retirados o vacíos. Usa el título y cualquier texto disponible. Si no hay evidencia alguna, usa `bug`, `app`, `areas: []`. No omitas ids ni inventes campos adicionales.

## Validación obligatoria

Después de escribir tu archivo asignado, ejecuta Python para comprobar: JSON válido, mismo número y orden de ids que el rango original, tipos/superficies/áreas permitidas, claves exactas y ausencia de duplicados. No modifiques `incidencias.jsonl` ni archivos de otros lotes.

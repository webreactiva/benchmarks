# Auditoría de seguridad de Quokka Bazaar

**24 de noviembre de 2026 · Revisión estática de la copia local**

**Decisión recomendada.** Posponer la exposición pública. El alta permite adquirir permisos administrativos, la recuperación de contraseña carece de un secreto impredecible y la API pública de archivos permite leer fuera del directorio documental. Cada defecto requiere una corrección independiente. Si esta versión ya estuvo expuesta, revisar las altas administrativas, los cambios de contraseña y los accesos a documentos. Conservar los registros antes de invalidar sesiones y rotar claves potencialmente expuestas.

## Hallazgos prioritarios

La gravedad estima el impacto para una tienda accesible desde Internet con datos reales. Las referencias corresponden a archivos y líneas de esta copia.

| Gravedad | Hallazgo y evidencia | Corrección y criterio de aceptación |
|---|---|---|
| Crítica | **Alta pública con privilegios administrativos.** El esquema admite el rol enviado por el cliente. El registro lo guarda y emite una sesión con ese rol. Las rutas administrativas confían en él. `lib/validation/schemas/auth.ts:3`, `app/api/auth/signup/route.ts:59`, `lib/server-auth.ts:113`. | Asignar en el servidor un rol fijo de comprador. Reservar las promociones a una operación administrativa auditada. Verificar que toda cuenta creada por el flujo público carece de acceso administrativo. |
| Crítica | **Recuperación de cuentas predecible.** El token se deriva del correo y de la hora, que la propia API devuelve. El flujo de restablecimiento acepta ese token para cambiar la contraseña. Una cuenta conocida puede quedar comprometida sin acceso al buzón. `app/api/auth/forgot-password/route.ts:13`, `app/api/auth/reset-password/route.ts:46`. | Generar 32 bytes aleatorios, guardar solo su resumen y entregar el token por correo. Consumirlo atómicamente, limitar solicitudes e invalidar sesiones anteriores. Comprobar caducidad y uso único. |
| Crítica | **Next.js vulnerable en App Router.** El lockfile fija Next.js 15.2.2 y el proyecto usa componentes de servidor. Esa versión está afectada por el aviso de ejecución remota asociado a React Server Components (CVE-2025-55182, seguimiento en Next.js CVE-2025-66478). `package-lock.json:8450`, `app/monitoring/internal-status/page.tsx:20`. | Actualizar Next.js y React a versiones mantenidas con las correcciones vigentes, regenerar el lockfile y reconstruir la imagen. Confirmar las versiones efectivas del artefacto desplegado. [Aviso del fabricante](https://nextjs.org/blog/CVE-2025-66478) |
| Alta | **Lectura y listado de archivos sin autorización.** La ruta pública une cadenas de la petición al directorio documental y devuelve contenidos o metadatos sin comprobar el destino real ni el propietario. El alcance llega a los archivos legibles por el proceso. `app/api/files/route.ts:8,20,49,62`, `lib/validation/schemas/files.ts:3`. | Resolver identificadores de documentos en servidor, autorizar por propietario y verificar que la ruta canónica queda dentro de la raíz, incluidos enlaces simbólicos. Cubrir lectura y listado con las mismas restricciones. |
| Alta | **Inyección SQL en tres operaciones.** La búsqueda de productos interpola el término, la de pedidos interpola el estado en una consulta que también filtra por dueño, y el registro de visitas incorpora cabeceras e identificadores a una sentencia de escritura. Pueden verse afectados la confidencialidad de los datos y la integridad del registro. `app/api/products/search/route.ts:93`, `app/api/orders/search/route.ts:81`, `app/api/tracking/route.ts:97`. | Usar filtros y escrituras de Prisma o parámetros enlazados para todos los valores. Verificar que texto con puntuación se procesa literalmente y que una búsqueda de pedidos solo devuelve filas del usuario autenticado. |
| Alta | **Sesiones y monitorización con credenciales débiles.** La firma JWT tiene una clave fija de reserva. El middleware de estado interno interpreta el rol sin verificar la firma. El acceso a registros SIEM acepta credenciales y una cookie de valor constante. Corregir un mecanismo deja los otros dos expuestos. `lib/server-auth.ts:12`, `middleware.ts:3`, `app/api/monitoring/auth/route.ts:5`, `app/api/monitoring/logs/route.ts:11`. | Exigir una clave de alta entropía al arrancar y verificar firma, caducidad y rol en servidor. Integrar el SIEM con sesiones individuales revocables. Verificar que la página y la API rechazan credenciales alteradas o caducadas. |
| Alta | **Solicitudes salientes controladas por el cliente (SSRF).** Soporte descarga una URL, añade una cabecera interna y devuelve el cuerpo. El asistente también contacta con un servidor MCP elegido por el cliente. El acceso a servicios internos depende de la red del despliegue. `app/api/support/route.ts:14`, `app/api/ai-assistant/route.ts:69,201`. | Admitir destinos previamente registrados y aplicar restricciones de salida tras resolución DNS y en cada redirección. Limitar tiempo y bytes de respuesta. Usar carga directa de imágenes en soporte. |
| Alta | **HTML de visitantes en el navegador del administrador.** Seguimiento guarda como IP el contenido de una cabecera y el panel lo inserta como HTML. Si el proxy acepta esa cabecera del cliente, un registro puede ejecutar contenido en una sesión administrativa. Soporte también interpreta la respuesta remota como HTML en el navegador del solicitante. `app/api/tracking/route.ts:58`, `app/admin/analytics/AnalyticsClient.tsx:366`, `app/support/SupportForm.tsx:103`. | Renderizar la IP como texto y aceptar cabeceras de origen solo de proxies de confianza. Para capturas, validar y recodificar imágenes. Verificar que el texto almacenado no crea elementos en el DOM. |
| Alta | **Contraseñas con MD5 sin sal.** Alta, acceso y restablecimiento usan un resumen rápido y determinista. Una filtración facilita recuperar contraseñas por diccionario. La lista de campos exportables incluye el resumen de contraseña. `lib/server-auth.ts:14`, `app/api/auth/signup/route.ts:46`, `app/api/user/export/route.ts:7`. | Migrar a Argon2id con sal individual, recalcular al autenticar y retirar el campo de las exportaciones. Exigir restablecimiento a cuentas afectadas por una exposición. |
| Alta | **Importe del pedido decidido por el comprador.** La API carga precios y cantidades del carrito, pero persiste el total recibido. Un cliente autenticado con un carrito puede registrar un importe que no corresponde a sus artículos. `app/api/orders/route.ts:39,130,153`. | Calcular el total en servidor con los precios autorizados y descuentos válidos. Confirmar que la suma persistida concuerda con las líneas y que variar el total enviado no altera el resultado. |
| Alta | **Documentos compartidos sin garantía de integridad.** El token cifra el recurso con AES-CBC sin autenticación y dispone de una clave fija de reserva. La ruta descifra el token y consulta el recurso identificado. `lib/share-crypto.ts:3`, `app/api/documents/share/route.ts:15,44`. | Usar tokens opacos aleatorios con recurso, caducidad y revocación en servidor. Invalidar enlaces antiguos y verificar que cualquier modificación del token deniega el acceso. |
| Alta | **Entidades externas XML habilitadas.** El importador administrativo carga DTD y sustituye entidades al procesar XML suministrado. Según los permisos del proceso, puede revelar archivos locales o agotar recursos. `app/api/admin/suppliers/import-order/route.ts:9,21`. | Desactivar DTD y entidades externas, imponer límites de tamaño y profundidad, y verificar que el importador acepta pedidos ordinarios sin resolver recursos externos. |
| Media | **Consumo de cupones sin atomicidad.** El contador se comprueba y actualiza en operaciones separadas antes de crear el pedido. Solicitudes concurrentes pueden superar el límite y un fallo posterior puede consumir un uso. `app/api/orders/route.ts:65,78,130`. | Registrar el pedido y reservar el uso del cupón en una transacción con actualización condicional. Comprobar que dos compras por el último uso producen un solo descuento y que un pedido fallido libera ese uso. |
| Media | **Configuración local incluida en la imagen.** La copia general incluye el archivo de entorno local porque la exclusión solo cubre el nombre exacto .env. Además, el cliente de compra referencia una variable de pago con prefijo público, visible en el paquete del navegador. `Dockerfile:10`, `.dockerignore:4`, `app/checkout/CheckoutClient.tsx:119`. | Excluir archivos de entorno de la imagen, inyectar secretos en ejecución y mantener cualquier secreto de pago en servidor. Inspeccionar las capas y el paquete cliente antes de publicar. |

## Orden de intervención

1. Restringir el acceso público mientras se actualiza el framework y se corrigen el registro, la recuperación, las sesiones y el acceso a archivos. Identificar qué versión y qué claves llegaron a producción.
2. Corregir las consultas, las salidas de red y la representación de contenido externo antes de reabrir las rutas afectadas. Revisar además los permisos del proceso y el acceso de red desde el contenedor.
3. Verificar la integridad de pedidos y cupones existentes, migrar los resúmenes de contraseña e invalidar los enlaces compartidos anteriores. Usar los criterios de la tabla para aceptar cada corrección.

## Alcance y límites

Se inspeccionaron estáticamente rutas de Next.js, validadores, autenticación, acceso a datos, componentes de interfaz, configuración de Docker y versiones fijadas. La severidad describe el comportamiento deducible del código. No se arrancó el servicio, no se probaron ataques ni se verificaron el proxy, los permisos efectivos, los datos o la versión de producción. La revisión de dependencias identifica un aviso crítico concreto y no constituye un inventario completo de avisos transitivos. La evidencia disponible no permite determinar si hubo accesos indebidos.
